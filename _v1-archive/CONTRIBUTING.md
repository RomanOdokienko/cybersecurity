# CONTRIBUTING

## Цель
Сохранить скорость разработки без потери воспроизводимости аудита и качества findings.

## Ветки
1. `main` — стабильная ветка.
2. `feature/*` — новая функциональность.
3. `fix/*` — исправления.
4. `docs/*` — изменения документации.

## Коммиты
1. Один коммит = одна логическая задача.
2. Сообщение коммита: кратко и предметно.
3. Не смешивать изменения скриптов, данных и UI без необходимости.

## Pull Request checklist
1. Что изменено и зачем.
2. Какие файлы/скрипты затронуты.
3. Как проверяли (команды, домены, артефакты).
4. Риски/ограничения.

## Правила для данных
1. Не удалять исторические артефакты без явного решения команды.
2. Если меняется формат normalized JSON — обновить схему и документацию.
3. Для спорных findings добавлять evidence, пригодный для перепроверки.

## Безопасность и этика
1. Только пассивные проверки публичных данных.
2. Запрещены эксплуатация, brute force, intrusive scanning.
3. Любые сомнительные кейсы — в ручную валидацию (`review_required`).
