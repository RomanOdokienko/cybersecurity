# ТЗ проекта (MVP): лидогенерация через пассивный security/compliance-аудит сайтов клиник

Версия: 2026-04-15  
Статус: контекст для внешнего размышления (Claude)  
Владелец: команда аудита клиник

---

## 1) Бизнес-контекст проекта

### 1.1 Что мы строим
Мы строим канал B2B-привлечения клиник через бесплатный короткий аудит сайта с последующим апсейлом в расширенный разбор и внедрение исправлений.

### 1.2 Что является ценностью для клиента
1. Понимание фактических рисков сайта (технических, репутационных, юридически чувствительных).
2. Понятная приоритизация: что важно исправлять в первую очередь.
3. Экспертное сопровождение по исправлениям.

### 1.3 Главная идея MVP
Количество критериев проверки не самоцель.  
Задача MVP: стабильно понимать, по каким сайтам оффер действительно сильный и уместный, а по каким — почти нет практической ценности для продажи на текущем этапе.

---

## 2) Аудитория и рынок

### 2.1 Фокус сегмента
1. Частные клиники и медцентры.
2. Сайты с формами записи/обратной связи.
3. Бизнес, чувствительный к потере лидов, репутации и комплаенсу.

### 2.2 Кто принимает решение
1. Собственник / генеральный директор.
2. Операционный или маркетинг-руководитель.
3. Технический подрядчик на стороне клиники.

### 2.3 Что важно для коммуникации
1. Факты и доказательства, а не общие формулировки.
2. Язык, понятный нетехническому владельцу.
3. Связка «проблема -> бизнес-эффект -> шаги исправления».

---

## 3) Продуктовая модель

### 3.1 Формат 20/80
1. Бесплатная часть: ограниченный срез findings для первого контакта.
2. Платная/демо часть: полный разбор, приоритеты, дорожная карта исправлений.

### 3.2 Что важно в бесплатной части
1. Коротко и по делу.
2. Только подтвержденные факты.
3. Без передачи полной технической глубины, которая является частью платной ценности.

---

## 4) Текущее состояние проверки

### 4.1 Текущие блоки аудита
1. SSL + redirects
2. File leaks
3. Open admin/CMS exposure
4. Security headers
5. Forms and patient data
6. DNS/email protection
7. Third-party scripts
8. Reputation/OSINT

### 4.2 Про критерии
1. Есть расширенная матрица (ранее использовалась модель на 52 критерия).
2. Число критериев может меняться.
3. Для MVP критично не количество пунктов, а практическая полезность для квалификации лидов.

### 4.3 Ограничения подхода
1. Только пассивная проверка публичных данных.
2. Без эксплуатации уязвимостей, брутфорса и интрузивных действий.
3. Проверка сайтов по одному.

---

## 5) Текущая операционная схема

1. Получение домена.
2. Быстрый скриптовый прогон (quick snapshot).
3. При необходимости ручная валидация спорных мест.
4. Формирование артефактов:
- raw evidence,
- normalized JSON,
- запись в дашборде,
- документ для коммуникации (html/pdf/md).

---

## 6) Инфраструктура и артефакты проекта

### 6.1 Что уже есть
1. Локальный проект с конфигами, шаблонами и скриптами.
2. Quick-пайплайн и экспорт данных в дашборд.
3. Базовые шаблоны оффера и расширенных отчетов.
4. Примеры ручного детального разбора (в т.ч. по 152-ФЗ screening).

### 6.2 Текущее ограничение визуализации
Дашборд сейчас агрегирует результат по блокам. Детальная покритериальная матрица отображается отдельными документами.

---

## 7) Требования к качеству и коммуникации

1. Подтвержденные факты отделять от гипотез.
2. Любой тезис в оффере должен иметь доказуемый источник.
3. Не использовать запугивание и не завышать формулировки.
4. Отчеты должны быть пригодны для общения с нетехническим владельцем.

---

## 8) Бизнес-метрики, которые хотим контролировать

1. Доля сайтов, где оффер реально формируется как полезный и убедительный.
2. Конверсия из оффера в демо.
3. Конверсия из демо в апсейл.
4. Время аналитика на один сайт.
5. Доля кейсов, где findings в коммуникации оказываются слабыми/спорными.

---

## 9) Открытые вопросы

1. Какой минимальный набор проверок дает максимум бизнес-пользы на старте?
2. Где проходит граница между «быстрым» и «детальным» анализом?
3. Какой формат оффера лучше конвертит в демо в сегменте клиник?
4. Как стандартизировать оценку полезности лида для продаж?
5. Какой уровень детализации показывать бесплатно, чтобы не обесценить апсейл?

---

## 10) One-line summary

MVP проекта — это система практической квалификации сайтов клиник для честного и конверсионного оффера, а не гонка за максимальным количеством технических критериев.
