# Agent Validation Protocol (Blocks 1-3)

Версия: 2026-05-11

## Цель

Финальный вердикт по метрикам выносится только агентной проверкой.

- Источник истины по метрике: агент + PoC.
- Скрипты не принимают финальные решения по метрикам.

## Жесткие правила

1. Проверка клиники выполняется только по одной клинике за раз.
2. При проверке одной клиники разрешено менять только ее audit JSON, ее detail-page и ее строку в таблице.
3. Массовый пересчет всех строк запрещен без явного отдельного решения.
4. Если скрипт и агент расходятся, в отчет идет агентный вердикт.

## Роли

1. `scripts/audit_site.py`
- legacy-инструмент сбора evidence;
- по умолчанию заблокирован политикой;
- запуск разрешен только с явным флагом `--legacy-script-audit`.

2. Агент
- проверяет сайт по смыслу в браузере;
- формирует PoC;
- выставляет финальный статус метрики.

3. `scripts/build_dashboard.py`
- рендер/синхронизация витрины;
- по умолчанию работает в точечном режиме (`--site-id` / `--site-ids`);
- полный пересчет разрешен только с явным флагом `--full-rebuild`.

## Обязательный pipeline на 1 клинику

1. Агентная проверка клиники по методологии.
2. Обновление JSON этой клиники с результатами агентной проверки.
3. Выставление `verification.<block>=true` только после завершенной проверки блока.
4. Рендер только этой клиники:
- `python scripts/build_dashboard.py --site-id <site-id>`
5. Зафиксировать режим проверки:
- `python scripts/set_verification_mode.py --site-id <site-id> --mode agent --set-verified`

## Маркер режима (обязательный)

В каждом `data/audits/*.audit.json` должен быть объект:

```json
"verification": {
  "mode": "agent",
  "mode_updated_at": "2026-05-11T12:34:56Z",
  "b2": true,
  "b3": true,
  "b4": true
}
```

Допустимые значения `mode`:
- `agent` — целевой режим (источник истины);
- `legacy_script` — legacy/исторический режим.

## Минимальные требования к PoC

Для каждой метрики:

1. `evidence_url` (или список URL);
2. краткий факт (1-3 строки);
3. итоговый `status` (`ок` / `проблема`).

## Запрещено

1. Автоматически ставить финальные метрики только по скриптовым эвристикам.
2. Массово обновлять блоки 2/3 по всем клиникам после изменения логики.
3. Делать финальный вывод по fallback-сигналам без агентного PoC.
